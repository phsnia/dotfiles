# RULES

## Core Principles

- Write minimal code. Implement only what is required.
- Keep it simple. Prefer straightforward solutions over clever abstractions.
- Avoid overengineering. No unnecessary classes, helpers, wrappers, or design patterns.
- Reuse existing code. Follow existing project conventions and reuse utilities when appropriate.
- Minimize changes. Modify only what is necessary to complete the task.
- No speculative features. Do not add functionality that was not requested.
- Avoid unnecessary dependencies. Use existing libraries and standard tools.
- Keep code readable. Use clear names and simple control flow.
- Handle errors appropriately. Add error handling only where it is needed.
- Do not duplicate code. Extract shared logic only when it meaningfully reduces duplication.
- Preserve existing behavior. Do not introduce unrelated changes or break existing functionality.
- No unnecessary comments. Write comments only when the intent is not obvious.

## Before Coding

- Inspect relevant files and existing patterns.
- Understand the requirement before making changes.
- Choose the smallest viable solution.

## After Coding

- Remove unused code and imports introduced by your changes.
- Run relevant tests or checks when available.
- Report what changed and any remaining issues.

## Golden Rule

Use the least amount of code necessary to solve the problem correctly. Do not add complexity without a clear, immediate need.
